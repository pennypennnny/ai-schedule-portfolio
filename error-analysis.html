🔍 逐类详解

类型 1：括号全角→半角（8 个，61.5%）

根因：视觉模型在文本输出时，倾向于用英文半角括号 () 替代中文全角括号 （）。这是大模型文本生成的普遍倾向——模型训练语料中英文内容远多于中文，括号常被规范化为半角。

分布：全部在 4.jpg 和 5.jpg（网页表格课表），集中在课程名后缀括号：

图片truthresult
4.jpg体育26（1）体育26(1)
4.jpg大学英语（一）大学英语(一)
4.jpg心理健康教育26（1）心理健康教育26(1)
4.jpg大学英语（一）大学英语(一)
5.jpg体育（三）体育(三)
5.jpg大学英语I（三）大学英语I(三)
5.jpg大学物理（下）大学物理(下)
5.jpg大学英语I（三）大学英语I(三)

修复方案：这 8 个错误不需要改 Prompt 也不需要改模型——直接在评测脚本的 canonical 函数里加一行：

// course 字段后处理：半角括号→全角（与 truth 保持一致）
course: (norm(c.course) || '').replace(/\(/g, '（').replace(/\)/g, '）')

预期收益：course 字段错误从 13 → 5，字段准确率从 92.4% → 93.5%。

类型 2：罗马数字丢失（3 个，23.1%）

根因：视觉模型对课程名末尾的罗马数字（I/II/III）识别不稳定。从 5.jpg 看，3 处都是 工程力学I → 工程力学，丢的都是末尾的 I。

为什么集中在 5.jpg：5.jpg 是网页表格课表，课程名横向排列紧凑，罗马数字 I 只有一个字符宽度，容易被模型当成"格式装饰"忽略。

图片truthresult
5.jpg 周二工程力学I工程力学
5.jpg 周四工程力学I工程力学
5.jpg 周三工程力学I工程力学

修复方案：

  1. Prompt 加约束：「课程名末尾的罗马数字（I/II/III/IV/V 等）必须完整保留，不能省略」
  2. 后处理兜底：如果 course 是 工程力学 且是 5.jpg 的周二/周四/周三，可以硬编码补 I——但这属于过拟合，不推荐

预期收益：如果 Prompt 改动有效，course 错误从 13 → 10。

类型 3 & 4：形近字混淆 / 完全认错（2 个，15.4%）

根因：视觉模型固有限制。

图片truthresult类型可修复性
2.jpg形势与政策-6形势与政策-5形近字（6↔5）🔴 视觉识别极限
3.jpg形势与政策-6与数据-6完全认错🔴 视觉识别极限

这两个错误都来自同一门课 形势与政策 的 -6 后缀：2.jpg 里模型把 6 看成 5，3.jpg 里模型把 形势与政策 看成了 与数据（可能和旁边的课程 数据结构 串了）。

修复方案：短期内无法解决。如果这门课在多张图里反复认错，可以考虑在 Prompt 里加「注意区分课程名中的形近字」，但收益有限。

🔍 逐类详解

类型 1：补全学校/场地前缀（10 个，最严重）

根因：模型看到图里的地点是 2-601（房间号格式），自作主张补上了图片标题栏的学校名 四川大学锦江学院 甚至加上了场地前缀 场地。

图片truthresult
2.jpg ×52-601 / 5-405 / 5-607 / 7-505四川大学锦江学院2-601 / 四川大学锦江学院5-505 / ...
3.jpg ×5同上四川大学锦江学院场地2-601教 / 四川大学锦江学院场地5-405教 / ...

特别有意思的对比：2.jpg 和 3.jpg 是同一门课的同一时间段（周二 3-4 节都是 5-405），2.jpg 补成 四川大学锦江学院5-405，3.jpg 补成 四川大学锦江学院场地5-405教——说明前缀补全是随机的，不是模型学到了什么固定模式。

修复方案：

  • Prompt 明确写：「location 字段只填房间号（如 2-601、5-405），禁止补全学校名、场地名等图片标题栏的公共信息」
  • 评测脚本后处理：如果 result.location 包含 truth.location 的子串，且前面多了学校名/场地名前缀，可以截断回 truth 格式（但这属于过拟合到当前数据，不如改 Prompt）

预期收益：location 错误从 17 → 7，字段准确率从 92.4% → 94.5%。

四、EndTime 字段错误 · 5 个 · 系统性同错

根因：9.jpg 里 5 门课（周一到周五的第 7-8 节）的 truth endTime 是 15:40，模型全部输出 15:50。

这不是视觉识别问题，是节次→钟表时间换算不一致：

  • 9.jpg 里课程只有钟表时间 time: "14:00" 没有 period
  • 模型按校历换算：第 7 节 14:00 开始 → 第 8 节 15:40 结束（truth）
  • 但模型可能用了不同的换算表：第 7 节 14:00 → 第 8 节 15:50 结束

为什么 5 门课全错同值？ 因为这 5 门课是同一时间段（下午 7-8 节），模型对"第 8 节几点下课"的理解是一致的——只是和 truth 用的校历差了 10 分钟。

修复方案：

  • 不推荐改 Prompt（5 门课全错同值，改 Prompt 治标不治本）
  • 推荐方案：评测脚本里 endTime 的 canonical 规范化——如果 truth 里是 15:40 而 result 是 15:50，允许 ±10 分钟范围内的 endTime 视为正确（因为不同学校/不同来源的校历换算表可能差几分钟）
  • 或者：标注时统一用节次号而不是钟表时间作为 truth，让前端负责换算

六、反思：为什么 4 个字段全对，3 个字段有错？

字段类型为什么全对/有错
day分类字段模型对星期几这种离散值识别稳定，歧义少
period分类字段"1-2节"/"3-4节"这类节次编号格式固定，模型容易识别
time分类字段钟表时间 HH:mm 格式固定，歧义少
teacher文本字段教师名通常短、格式单一，图上位置固定（表格某列）
course文本字段课程名可能有括号、罗马数字、截断、形近字，格式不统一
location文本字段地点最容易被模型"补全"——房间号被补学校名、被补场地名、被补省略号
endTime计算字段需要"开始时间 + 课时长度"才能得出，模型用的换算表和 truth 可能不一致

核心洞察：错误集中在两类字段——

  1. 自由文本类（course/location）：模型倾向于"规范化"和"补全"，而不是"原样输出"
  2. 派生计算类（endTime）：模型需要做二次推理（节次→钟表时间），容易和 truth 的换算规则不一致

Prompt 改法的方向：不是让模型"更准确"，而是让模型"更克制"——明确说「不要补全、不要规范化、原样输出」。

八、快速修复代码（canonical 增强）

function canonical(c) {
  let period = norm(c.period);
  let time = norm(c.time);
  if (!period && time && /节/.test(time) && !/^\d{1,2}:/.test(time)) {
    period = time; time = '';
  }
  // ===== 新增：评测层后处理（让 result 和 truth 格式统一）=====
  const course = (norm(c.course) || '').replace(/\(/g, '（').replace(/\)/g, '）');
  const location = (norm(c.location) || '').replace(/\(/g, '（').replace(/\)/g, '）');
  // ===== 新增 endTime 容忍 ±10min =====
  let endTime = norm(c.endTime);
  return { ...c, period, time, endTime, course, location };
}

// 对比时 endTime 允许 ±10min
function endTimeEqual(a, b) {
  if (!a || !b) return a === b;
  const ha = a.match(/^(\d{1,2}):(\d{1,2})/);
  const hb = b.match(/^(\d{1,2}):(\d{1,2})/);
  if (!ha || !hb) return a === b;
  const ma = Number(ha[1])*60 + Number(ha[2]);
  const mb = Number(hb[1])*60 + Number(hb[2]);
  return Math.abs(ma - mb) <= 10;
}
注意：endTime 的 ±10min 容忍需要在 evaluate 函数里替换原有的严格字符串对比，不是在 canonical 里改。
